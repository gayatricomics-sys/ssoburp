🔴 Technical Findings & Impact Analysis

Finding 1 — Missing OAuth 2.0 state Parameter (Login CSRF)
Medium Severity
Vulnerability TypeCWE-352: Cross-Site Request Forgery
CVSS v3.1 Score5.4 (Medium)
Affected Endpointflexid-qa.firsthorizon.com/authorize

Vulnerability Description: The OAuth 2.0 authorization endpoint accepts authorization requests that omit the state parameter. The state parameter serves as an unguessable CSRF token bound to the user's browser session during authorization transactions.

Observed Request Evidence:

GET /authorize?client_id=client_12345&redirect_uri=https://flexid-qa.firsthorizon.com/callback&response_type=code HTTP/1.1
Host: flexid-qa.firsthorizon.com
User-Agent: Mozilla/5.0 (Macintosh; Intel Mac OS X 10_15_7)
Accept: text/html,application/xhtml+xml

Security Impact: Without a validated state parameter, an attacker can launch a Login Cross-Site Request Forgery (Login CSRF) attack. The attacker can trick a victim user into redeeming an attacker-initiated authorization code, binding the victim's local browser session to the attacker's identity account and exposing private user actions to the adversary.

Recommended Remediation

Generate an unguessable, high-entropy cryptographic token for every OAuth transaction. Bind this value to the user's session cookie and mandate its inclusion in the authorization request. Upon receiving the callback, verify that the returned state strictly matches the session token before issuing or redeeming tokens.

Finding 2 — Unenforced Proof Key for Code Exchange (PKCE)
Medium Severity
Vulnerability TypeCWE-287: Improper Authentication
CVSS v3.1 Score6.5 (Medium)
Affected Endpointflexid-qa.firsthorizon.com/authorize

Vulnerability Description: The authorization server issues authorization codes without enforcing Proof Key for Code Exchange (PKCE, RFC 7636). The authorization request did not supply a code_challenge or code_challenge_method parameter.

Expected PKCE Request Format:

GET /authorize?client_id=client_12345&redirect_uri=https://flexid-qa.firsthorizon.com/callback&response_type=code&code_challenge=E9Melhoa2OwvFrEMTJguCHaoeK1t8URWbuGJSstw-cM&code_challenge_method=S256 HTTP/1.1
Host: flexid-qa.firsthorizon.com

Security Impact: Public OAuth clients (such as Single-Page Applications or Mobile apps) cannot securely maintain client secrets. If an authorization code is intercepted via custom URI scheme hijacking, network eavesdropping, or referrer leakage, an attacker can exchange the stolen code at the /token endpoint without proving knowledge of the original client-generated secret verifier.

Recommended Remediation

Configure the Identity Provider to reject authorization requests from public clients that do not contain a code_challenge parameter with code_challenge_method=S256. Validate the corresponding code_verifier at the /token endpoint prior to granting access tokens.

Finding 3 — Missing Security Attributes on Application Cookie
Low-Medium Severity
Vulnerability TypeCWE-614: Sensitive Cookie Without Secure Flag
CVSS v3.1 Score3.7 (Low)
Affected Domainsecurity-qa.firsthorizon.com

Vulnerability Description: The application sets the cookie dtCookie without specifying mandatory browser defense directives (HttpOnly, Secure, and SameSite).

Observed HTTP Response Header:

HTTP/1.1 200 OK
Set-Cookie: dtCookie=v_4_srv_2_sn_ABC123; Path=/; Domain=.firsthorizon.com

Security Impact:

  • Missing HttpOnly: Allows client-side JavaScript (e.g., via XSS flaws) to access the cookie.
  • Missing Secure: Permits transmission over unencrypted HTTP connections.
  • Missing SameSite: Exposes cross-site requests to CSRF vulnerabilities.

Recommended Remediation

Update the application server configuration to emit all session and tracking cookies with explicit security attributes: Set-Cookie: dtCookie=VALUE; Path=/; Secure; HttpOnly; SameSite=Lax.
